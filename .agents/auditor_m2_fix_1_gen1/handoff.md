## 1. Observation

### Source Code Audited
We performed static analysis on the following files:
*   **Validation Layer**: `dashboard/src/lib/validation.ts`
    *   *Line 3-20*: `SafeStringSchema` implements dynamic unescaping and escaping to prevent double-escaping and sanitize HTML characters.
    *   *Line 23-31*: `BudgetSchema` performs dynamic string coercion to strip `$` and commas and cast values to floats.
    *   *Line 37-46*: `CommercialSchema` maps string representations (`"true"`, `"1"`) and numeric values to booleans.
    *   *Line 49-56*: `LeadMetadataSchema` defines schemas for `budget`, `request_date`, and `commercial` and calls `.strip()` to reject unknown or prototype-polluting keys at the payload boundaries.
*   **Next.js API Proxy**: `dashboard/src/app/api_proxy/[...slug]/route.ts`
    *   *Line 36*: `ALLOWED_ROUTES` defines an explicit SSRF allowlist.
    *   *Line 49-57*: Loop decoding URI components (`decodeURIComponent`) up to 10 iterations to mitigate double-encoding path traversal bypasses.
    *   *Line 59-67*: Rejects requests containing `..` or `\\` in path or decoded path with a `403 Forbidden` response.
    *   *Line 108-132*: Extracts tenant ID and validates format using a strict UUID regex, blocking invalid requests with `400 Bad Request`. Rejects missing headers/params except on allowlisted bypass routes (`api/v1/ping`, `api/v1/config`, `api/health`).
    *   *Line 144-159*: Performs dynamic request body parsing and schema-based filtering via `LeadSchema.partial().parse(json)`.
    *   *Line 174-191*: Performs dynamic response body parsing and schema filtering via `LeadsListSchema.parse(json)` or `LeadSchema.parse(json)`.
*   **UI Leads Component**: `dashboard/src/app/leads/page.tsx`
    *   *Line 129-296*: `CustomMetadataBento` dynamically parses and formats incoming metadata.
    *   *Line 328*: Dynamic list validation using `LeadsListSchema.parse(rawList)`.
    *   *Line 395-422*: Page header and layout use authentic Tailwind CSS classes inheriting from the Heritage Design System tokens (e.g., `text-tertiary`, `border-primary/5`, `bg-card`).

## 3. Caveats

*   **Mock Backend**: The mock backend API (`scripts/mock-api.js`) runs locally and serves partitioned JSON state. Real integration with a live backoffice SaaS database was not tested under this E2E setup, but the mock architecture mimics it correctly.
*   **Port Lockouts**: Sockets remaining in a TIME_WAIT state can temporarily block the E2E port (8001). This was addressed by clearing running tasks and waiting for OS socket expiration.

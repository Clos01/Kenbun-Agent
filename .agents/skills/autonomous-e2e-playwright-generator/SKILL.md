# 🎭 Autonomous E2E Playwright Generator

The **Autonomous E2E Playwright Generator** equips the Swarm to automatically scaffold, execute, and self-heal comprehensive browser-based integration tests covering complete multi-page user journeys.

---

## 🎯 When to Activate

Trigger this skill immediately when:
- Creating or updating full user journeys (e.g. Inbound Lead -> Estimate Valuation -> Invoice Completion).
- Verifying cross-page data persistence across Next.js dashboards.
- Automating regression testing prior to production releases.
- Generating headless browser test scripts with automatic retries, network mocking, and video/trace artifacts.
- Debugging flaky CI/CD test runs and selector regressions.

---

## 🏗️ The 8-Phase Business Pipeline Test Matrix

Playwright tests generated by this skill follow the 8-phase pipeline:
1. **Phase 1: Inbound Lead Capture:** Submit form -> assert webhook triggered & cleaned.
2. **Phase 2: CRM & Planka Sync:** Assert card created on board and moved to "In Review".
3. **Phase 3: AI Valuation:** Trigger calculation -> assert estimate generated in UI.
4. **Phase 4: Logistics & Calendar:** Submit access code -> verify event scheduled.
5. **Phase 5: Automated Upsell:** Advance state -> assert follow-up prompt displayed.
6. **Phase 6: Live Market Scanner:** Assert property metadata status update.
7. **Phase 7: Team Dispatch:** Verify dispatch notification modal/payload.
8. **Phase 8: Close-out & Invoicing:** Trigger client sign-off -> assert card moved to "Completed".

## 🛡️ Playwright Generation Best Practices

### 1. User-Facing Resilient Selectors
Never use fragile XPath or nth-child selectors. Always prioritize accessibility roles and user-facing text:
```typescript
// ❌ Fragile: Breaks on CSS layout change
await page.click('div > div:nth-child(3) > button');

// ✅ Resilient: Uses accessible role and name
await page.getByRole('button', { name: /request estimate/i }).click();
await expect(page.getByRole('heading', { name: /estimate summary/i })).toBeVisible();
```

### 2. Auto-Waiting & Assertions
Always use web-first assertions (`await expect(locator).toHaveText(...)`) instead of arbitrary `page.waitForTimeout()` sleeps.

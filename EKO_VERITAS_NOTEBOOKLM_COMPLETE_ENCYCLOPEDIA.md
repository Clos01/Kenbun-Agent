## 1. System Purpose: What the App Does

**Eko Veritas** is an autonomous, closed-loop **Quality Assurance (QA), Telemetry, and Self-Healing Prompt Engineering Platform** for enterprise voice agent fleets powered by ElevenLabs Conversational AI.

### Core Value Propositions:
1. **$100\%$ Call Evaluation (Zero Sampling Bias):** In traditional QA, humans sample $<2\%$ of calls. Eko Veritas intercepts 100% of completed phone calls via webhooks and automatically grades the transcript against objective behavioral criteria.
2. **Deterministic Quality Scoring:** Converts AI judge verdicts into binary $100$ (Pass) vs. $0$ (Flagged Failure) scores, calculating real-time fleet pass rates and surfacing quality anomalies.
3. **Closed-Loop Self-Healing Prompts:** When a customer complains, Anthropic Claude 3.5 Sonnet diagnoses which line in the agent's system prompt failed, writes a surgical prompt patch, and creates a new evaluation rule to permanently catch future violations.
4. **Human-in-the-Loop (HITL) Governance:** All prompt corrections and newly invented criteria are placed in a visual Revision Queue with side-by-side diffs, requiring explicit operator approval before deploying live to ElevenLabs.
5. **Defensive Ingestion & Inventory Reconciliation:** Automatically reconciles local database records with remote ElevenLabs account inventory, detecting unimported agents and flagging cross-account or deleted agent IDs with deep-links to official API documentation.

## 2. Scope Boundaries: What the App Currently Does NOT Do

To maintain crystal clarity on architecture and prevent false assumptions, the system explicitly defines what is outside current scope:

1. **No Live In-Flight Audio Stream Interception:** Eko Veritas is a **post-call** ingestion and evaluation platform. It does not tap into live WebRTC/RTP audio streams during a call in progress; evaluations execute within seconds after the call terminates.
2. **No Unreviewed Autonomous Deployments:** The platform **never** pushes AI-generated prompt patches to production without human approval in the Revision Queue.
3. **No In-Browser Speech-to-Text Processing:** The app does not transcribe raw audio files using local Whisper models; it ingests structured turn-by-turn transcripts generated by ElevenLabs' conversational speech recognition pipeline.
4. **No Multi-Provider Audio Mixing (Yet):** Ingestion is currently optimized for ElevenLabs Conversational AI webhooks (Twilio Media Streams and Vapi bridges are planned on the future roadmap).
5. **No Direct Production Database Writes from Webhook Nodes:** Webhook traffic never writes directly from external n8n instances to Azure PostgreSQL; all traffic routes through the secure `/api/ingest/elevenlabs` endpoint with HMAC signature validation.

## 7. Backend Logic Flow: The 5 Core Engines

```mermaid
flowchart TD
    A[ElevenLabs Call Finishes] -->|HTTP POST| B[/api/ingest/elevenlabs]
    B --> C[(1. Durable Raw Write: webhook_events)]
    C --> D{HMAC Signature Valid?}
    D -->|No| E[Log Signature Mismatch]
    D -->|Yes| F[2. Normalise Event: unwrapEnvelope]
    F --> G[(Upsert: calls, transcripts, recordings)]
    F --> H{Check: eval_criteria exists?}
    H -->|No| I[(Auto-Insert: eval_criteria)]
    H -->|Yes| J[3. Score Evaluations]
    J -->|Pass| K[(Insert: eval_results Score 100)]
    J -->|Fail| L[(Insert: eval_results Score 0 Flagged)]
    
    M[Customer Feedback Submitted] --> N[4. Claude 3.5 Sonnet Diagnoser]
    N --> O[Pinpoint Prompt Line & Draft Revision]
    N --> P[Invent New Proposed eval_criteria]
    O --> Q[(Insert: prompt_revisions 'pending')]
    
    R[Operator Approves Diff] --> S[5. sync_outbox Worker]
    S -->|PATCH /v1/convai/agents| T[ElevenLabs Live Fleet Updated]
```

### Engine 1: Durable Webhook Ingestion & Cryptographic Proof
* **Entry:** `src/app/api/ingest/elevenlabs/route.ts`
* **Zero Data Loss Invariant:** The raw HTTP request text is inserted into `webhook_events` **before** any JSON parsing or authentication occurs. If a signature fails or JSON is malformed, the raw string is preserved for operator inspection.
* **Cryptographic Provenance:** Uses `crypto.createHmac('sha256', secret)` with `crypto.timingSafeEqual` over SHA-256 normalized digests to prevent timing attacks.

### Engine 2: Normalisation & Automatic Criteria Provisioning
* **Entry:** `src/lib/ingest/elevenlabs.ts`
* **Envelope Unwrapping:** Strips n8n execution wrappers (`{body, query, params}`) to extract pure conversation payloads.
* **Dynamic Rubric Provisioning:** When evaluation results arrive for an unseen rule name, the system dynamically inserts a new row into `eval_criteria` under the `Standard Post-Call Rubric`.

### Engine 3: Deterministic Scoring & Flagging Algorithm
* **Scoring Rules:**
  - `pass`, `success`, `true`, `passed` $\longrightarrow$ Score = **$100$**, `is_flagged = false`.
  - `fail`, `failure`, `error`, `false` $\longrightarrow$ Score = **$0$**, `is_flagged = true`.
  - `unknown`, `n/a` $\longrightarrow$ Skipped (non-applicable).
* **Mathematical Fleet Pass Rate:**
  $$\text{Fleet Pass Rate} = \left( \frac{\text{Count of Evaluations with Score } 100}{\text{Total Scored Evaluations}} \right) \times 100$$

### Engine 4: Claude Self-Healing Feedback Diagnosis Loop
* **Entry:** `src/app/(dashboard)/call-telemetry/feedback-actions.ts`
* **Model:** Anthropic `claude-3-5-sonnet` (System 2 Diagnoser).
* **Payload:** Ingests the customer complaint string and the agent's current `system_prompt`.
* **Output:**
  1. `suggested_revision`: Minimal, surgical system prompt rewrite.
  2. `rationale`: Plain-English explanation of why the change prevents the error.
  3. `proposed_eval_criterion`: A brand-new boolean quality test question to ensure future compliance.

### Engine 5: Outbox Sync Queue & ElevenLabs Fleet Reconciliation
* **Entry:** `src/app/(dashboard)/voice-agents/actions.ts` & `src/lib/sync-worker.ts`
* **Transactional Outbox:** When a prompt is updated or approved, a task is written to `sync_outbox`. The background drain worker pulls pending items, transmits HTTP `PATCH` requests to ElevenLabs `/v1/convai/agents/{id}`, and handles retries with exponential backoff.
* **Reconciliation Sentinel:** Compares remote agent list against local database rows to identify `unimportedRemote` and `crossAccountErrors`.

### Table Dictionary & Key Invariants:
1. **`webhook_events`:** Append-only log of every raw request body arriving from external webhooks.
2. **`voice_agents`:** Agent identity registry mapping local tenant profiles to external ElevenLabs agents.
3. **`calls`:** Discrete telephony sessions uniquely indexed on `elevenlabs_conversation_id` for idempotency.
4. **`transcripts`:** Full text turns between agent and caller.
5. **`recordings`:** Storage URLs and duration metadata for call audio replays.
6. **`eval_rubrics`:** Grouping containers for quality rules (e.g. *Standard Post-Call Rubric*).
7. **`eval_criteria`:** The individual behavioral rules and boolean test prompts.
8. **`eval_results`:** Scored outcomes per call per criterion ($100$ Pass vs. $0$ Fail) with AI written explanations.
9. **`customer_feedback`:** Caller complaints and qualitative feedback submissions.
10. **`prompt_revisions`:** Version-controlled prompt diffs generated by Claude awaiting operator review.
11. **`integrations`:** Encrypted API keys scoped strictly by `tenant_id`.
12. **`sync_outbox`:** Durable queue for outbox synchronization to external ElevenLabs endpoints.
